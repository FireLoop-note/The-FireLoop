# Fire Loop 管道协议 v1（M1a）

配套文档：`docs/fire-loop-方案.md`。本文件是 T1（服务端）和 T2（客户端）共同遵守的线协议，双方都按本文写代码。

## 1. 传输

- Windows 命名管道：`\\.\pipe\fireloop-implant`
- 消息编码：UTF-8 JSON，一条消息一行，以 `\n` 结尾（JSON Lines）
- 单行上限：65536 字节，超限断开连接并记日志
- 连接模型：短连接。一个客户端完成一次请求/响应后关闭，服务端串行 accept
- M1a 不做并发多客户端，不推事件

## 2. 连接流程（强制顺序）

1. 客户端连接管道（连接超时 2000ms）。
2. 客户端在 2000ms 内发出首帧 hello：
   ```json
   {"v":1,"type":"hello","token":"<64位hex>"}
   ```
3. 服务端校验 token：
   - 正确 → 回 `{"v":1,"type":"hello_ok","agent":"Fire Loop","version":"0.1.0"}`
   - 错误或缺失 → 回错误帧（`code":"bad_token"`），然后断开连接
4. 过鉴权后，客户端发请求；服务端逐条响应。

## 3. 请求（客户端 → 服务端）

```json
{"v":1,"id":"<唯一字符串>","type":"ping"}
{"v":1,"id":"<唯一字符串>","type":"task","text":"<任务文本>"}
```

- `id`：客户端生成，响应用同一个 id 回传。
- `text`：M1a 必填，最大 4096 字符。

## 4. 响应（服务端 → 客户端）

```json
{"v":1,"id":"<同请求>","type":"result","ok":true,...}
```

- ping → `{"v":1,"id":"...","type":"result","ok":true,"text":"pong"}`
- task → `{"v":1,"id":"...","type":"result","ok":true,"text":"收到任务","text_len":N}`
  - M1a 只回显，不执行、不存长期记忆。

## 5. 错误

```json
{"v":1,"id":"...","type":"result","ok":false,"code":"<错误码>","message":"<可读说明>"}
```

| code | 含义 |
|---|---|
| `agent_offline` | CLI 侧错误：连不上 agent（不走协议帧，CLI 自己打印） |
| `bad_token` | 首帧 token 错误或缺失 |
| `bad_json` | 不是合法 JSON |
| `bad_msg` | 缺字段或类型不对（如 task 缺 text） |
| `too_large` | 单行超过 65536 字节 |
| `unknown_type` | 未知 type（M1a 只认 ping/task） |
| `timeout` | CLI 侧：等响应超时（CLI 自己打印） |
| `internal` | 服务端内部错误 |

## 6. 超时与退出码

| 项 | 值 |
|---|---|
| CLI 连接管道 | 2000ms |
| hello 响应等待 | 2000ms |
| 单请求响应等待 | 5000ms |

CLI 退出码约定：

- 0：成功
- 1：agent 没在跑（agent_offline）
- 2：连接/响应超时
- 3：协议错误（bad_token / bad_json / bad_msg / 服务端返回 ok=false）
- 4：内部错误

超时必须让 CLI 明确报错退出，**绝不挂死**。

## 7. 安全红线（M1a）

- 只接受 `hello` / `ping` / `task` 三种 type；
- `task.text` 只回显，不执行命令、不写长期记忆；
- 不开放任意命令执行、不开放文件系统遍历；
- 日志只记 `text_len` 和 sha256 前 8 位，不记原文；
- 服务端对非法输入只回错误并断开，不崩溃、不空转。

## 8. 版本

- `v = 1`。M1b 若加事件推送，升 `v = 2`，服务端保留对 v1 的兼容窗口。
