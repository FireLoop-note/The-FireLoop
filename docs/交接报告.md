## 1. 项目一句话

做一个不依赖小鲸鱼现有框架的 Windows 常驻程序，让系统能直接叫她、事件能直接通知她、能用 API 的地方不模拟人点击。

注意：新项目是独立仓库，不 import 小鲸鱼现有代码，不复制它的框架。旧项目只作为历史参考。

---

## 2. 项目边界

第一阶段做：

- 用户登录后常驻的 agent；
- 命名管道服务端；
- xjy_cli 管道客户端；
- 用户级协议 xiaojingyu:// 和文件右键；
- 文件、剪贴板、前台窗口事件；
- API 优先的系统能力。

第一阶段不做：

- Windows 服务；
- 内核驱动；
- 替换 explorer；
- 登录凭据提供者；
- COM Shell Extension DLL；
- 双进程“服务负责想、代理负责看”的拆分；
- 把旧项目的记忆、技能、UI 搬进来。

服务化放到最后，甚至不做。原因见第 7 节。

## 6. 推荐架构

第一阶段：

    agent（Python，登录后常驻）
      ├ 持有全部状态
      ├ 命名管道服务端
      ├ 文件、剪贴板、前台窗口事件
      ├ 任务队列、去抖、去重、配额
      └ 后续再接模型和工具

    xjy_cli（无窗口 Python 程序，后续打包 exe）
      └ 连接管道，发送 ping 或 task

    HKCU 注册表
      ├ xiaojingyu:// 协议
      ├ 文件右键
      └ 文件夹右键

管道名建议：\\.\pipe\xiaojingyu-implant

消息格式：一行一条 JSON，UTF-8，首帧带 token。

建议请求：

    {"id":"a1","type":"ping"}
    {"id":"a2","type":"task","text":"打开记事本","src":"cli"}

建议响应：

    {"id":"a1","type":"result","ok":true,"text":"pong"}
    {"id":"a2","type":"result","ok":true,"text":"收到任务"}

第一阶段只做回显/路由，不调模型。

## 7. 为什么第一阶段不做 Windows 服务

- 服务在 Session 0，不能弹窗，不能操作登录用户桌面。
- 服务默认 LocalSystem，写文件会改变属主，用户可能删不掉。
- 服务安装需要管理员权限，装不上整个产品就废。
- 现有手眼能力，比如 UIA、截图、键鼠，全部只能在用户会话里跑。
- 双进程会让简单工具调用多一次 IPC 往返，超时和重试都要重写。
- 记忆/技能是文件，不需要搬；搬过去只会双写冲突。

如果以后确实需要登录前/无用户会话也能干活，再单独评估服务化。到那时边界也应该是：

- 用户会话进程持有全部有意义的状态和手眼；
- 服务只做无界面的长任务，比如监控、定时、批量；
- 不是“服务负责想、代理负责看”。

### M1a 管道 + CLI

预计 2 到 3 天。

做：

- agent 启动命名管道服务端；
- xjy_cli ping / task；
- 单实例；

- xjy_cli task 能把任务送到 agent；
- agent 退出后 CLI 明确报“没在跑”；
- 不写注册表、不装服务、不接模型。

### M1b 系统身份 + 事件

预计 3 到 4 天。

做：

- HKCU 注册 xiaojingyu:// 协议；
- 文件/文件夹右键；
- 登录启动 agent；
- 文件事件 ReadDirectoryChangesW；
- 剪贴板 AddClipboardFormatListener；
- 前台窗口 SetWinEventHook；
- 事件去抖、去重、配额、日志 event_dispatch。

验收：

- xiaojingyu://task?text=打开记事本 能触发；
- 右键文件她能收到并回话；
- 丢文件进监控目录出现 event_dispatch，全程没截图；
- agent 退出 CLI 明确报错不挂死。

### M2 API 工具替换

预计 5 到 7 天。

先做：

- 文件操作 IFileOperation；
- 音频 IAudioEndpointVolume；
- 亮度 WmiMonitorBrightnessMethods；
- 计划任务 ITaskService；
- 启动程序 App Paths / Shell.Application。

每次替换后真跑一次，确认不弹窗、不点鼠标。

### M3 可选的服务化

只有确实需要“登录前也能跑”才做。否则不做。

- pywin32 未安装。做命名管道 ACL 或服务化时会需要，安装前先确认方案。

- 没有远程 Git 仓库，也没有异机备份。
- 没有专门的测试机，当前只有这台 Windows 11。
- 没有应用图标和品牌资源，新项目不要直接依赖旧项目的 whale_blue.ico。

- 管道协议和 token 鉴权的正式定义。
- xjy_cli 的最终形态：Python 脚本还是 PyInstaller exe。
- 协议和右键的注册/卸载脚本。
- 事件源的权限和隐私口径。
- 画词/回复风格是否复用旧人格，还是新项目独立定义。
- 测试矩阵：管理员/标准用户，登录/未登录，agent 在/不在。
- 安装包和卸载后的清理规则。
- 代码签名和发布流程。

## 10. 安全与隐私

- 管道首帧必须带 token；服务端校验调用方 SID。
- token 只写当前用户目录，不放 ProgramData 公共可读位置。
- CLI 只接受任务文本和文件路径，不开放任意命令执行。
- 事件先到本地队列，命中白名单/规则才升级成任务。
- 剪贴板默认不写入长期记忆，敏感内容过滤。
- 文件监听只监控白名单目录，不监控整盘。
- 开机自启走 HKCU，不装服务、不请求管理员。
- 任何系统级改动先出方案，得到主人同意再做。
- 删除文件一律放回收站，不清空回收站。
