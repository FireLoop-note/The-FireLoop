# Fire Loop 验收套件使用说明

本文件说明 `tests/acceptance/run_m1a_acceptance.py` 怎么跑、结果怎么读、隔离怎么做，
以及为什么**用户电脑上真实 agent 常驻时也能安全验收**。

适用范围：M1a 起的所有里程碑。每个里程碑做完，由 QA 跑一遍并把结果报给 Lead。
当前覆盖 **M1a（20 项）+ B1（9 项）+ B2（10 项）+ M2（9 项）= 48 项**。

---

## 1. 它是什么

`run_m1a_acceptance.py` 是项目**行为验收总入口**，不是单元测试的替代：

- 真起 agent 进程、真跑 CLI 子进程、真跑安装/卸载脚本；
- 每次运行都在**完全独立**的管道、互斥体、数据目录、注册表前缀里跑，和真实常驻 agent 零冲突；
- 人类可读输出 + 机器可读 JSON 双份结果；
- 成功、失败、脚本内部异常，所有路径都会清场（杀测试进程、删临时目录、删测试注册表项、删计划任务）。

单测（`python -m unittest discover -s tests -v`）验逻辑，本套件验真实进程/真实系统行为，两边都要跑。

---

## 2. 快速运行

前置：Windows 11，解释器 `D:\Python\python.exe`（3.15.1），零第三方依赖，不用 pip install。
B1 项需要 `install/launch.py` 和 `D:\Python\pythonw.exe`（install 脚本默认探测）。

```powershell
cd D:\ds植入式
$env:PYTHONPATH = "$PWD\src"
python tests\acceptance\run_m1a_acceptance.py
```

默认全跑（M1a + B1 + B2 + M2），本机实测约 19~23s；M2 只连本机 127.0.0.1 的 mock LLM 服务，全程不联网、不调用真实 DeepSeek API、不碰真实 secrets.json，不装服务。

### 参数

| 参数 | 作用 |
|---|---|
| `--suite LIST` | `all`（默认）或逗号分隔的 `m1a,b1,b2,m2`；扩展套件复用 M1a 起的测试 agent，所以选 b1/b2/m2 时 m1a 会一起跑 |
| `--json <path>` | 机器可读结果路径；默认写 `%TEMP%\fireloop-acceptance\result-<时间>-pid<pid>.json` |
| `--skip-graceful-exit` | 跳过 Ctrl+Break 优雅退出项并标 SKIP（无控制台环境用；**默认真测**） |
| `--enable-desktop-events` | 真测剪贴板 / 前台窗口事件（会短暂改动当前桌面和剪贴板；默认 SKIP，**SKIP 不算通过**） |
| `--enable-result-window` | 真测结果展示窗口（会短暂弹窗；默认 SKIP，**SKIP 不算通过**） |

常用跑法：

```powershell
# 只做 M1a 基线回归（20 项，最快）
python tests\acceptance\run_m1a_acceptance.py --suite m1a

# B1 验收（M1a 20 + B1 9）
python tests\acceptance\run_m1a_acceptance.py --suite b1

# B2 验收（M1a 20 + B2 10）
python tests\acceptance\run_m1a_acceptance.py --suite b2

# M2 模型链路（用本机 mock LLM，不联网）
python tests\acceptance\run_m1a_acceptance.py --suite m2

# 全量 + 桌面事件真测（会操作剪贴板/前台窗口）
python tests\acceptance\run_m1a_acceptance.py --enable-desktop-events

# 全量 + 结果窗口真测（会短暂弹窗）
python tests\acceptance\run_m1a_acceptance.py --enable-result-window
```

### 跨用户 SID 拒绝（独立脚本）

需要 Lead 建好的 `fl_test` 标准账户（task-9）。没有账号时主套件里 B2-10 记 **SKIP**（明确不是 PASS）：

```powershell
# 管线自检（当前用户跑同一套流程，应得到 pong，不需要 fl_test）
python tests\acceptance\run_cross_user_sid_check.py --selftest

# 真实跨用户拒绝（交互输入 fl_test 密码；或设环境变量 FL_TEST_PASSWORD）
python tests\acceptance\run_cross_user_sid_check.py --user fl_test
```

退出码：`0` = 拒绝路径符合预期（Windows DACL 层或协议层，二者都算）；
`1` = 安全问题/脚本失败；`2` = 环境不具备（没有账号/密码/建不了计划任务），**不是通过**。

## 3. 输出怎么读

### 终端输出

每项一行，格式：

```
[PASS] 2. cli ping → pong，退出码 0 —— exit=0 stdout=pong 耗时=0.10s  (0.10s)
[FAIL] 4. ping/task 连续 5 轮不出现偶发 agent_offline —— #3 ping exit=1 stdout=''  (1.20s)
[SKIP] B2-8. 前台窗口事件 … —— 默认跳过前台窗口真实操作；加 --enable-desktop-events 才真测（SKIP 不算通过）  (0.00s)
```

- `PASS`：这条验收项通过；
- `FAIL`：这条不通过，`——` 后面是失败现场（退出码、stdout/stderr 摘要、耗时等）；
- `SKIP`：这条**没测**（环境限制或显式开关未开），**SKIP 不是通过**，交付报告要逐项说明；
- 行尾 `(…s)` 是该项耗时；
- 末尾汇总：`验收结果：48 项，PASS 44 / FAIL 0 / SKIP 4，耗时 19.31s`，并列出所有失败项。

### 机器可读 JSON

结构（`schema = fireloop.acceptance.v1`）：

```json
{
  "schema": "fireloop.acceptance.v1",
  "suites": ["m1a", "b1", "b2", "m2"],
  "started_at": "...", "finished_at": "...", "duration_s": 10.41,
  "python": {"executable": "...", "version": "3.15.1"},
  "isolation": {
    "pipe_name": "\\\\.\\pipe\\fireloop-accept-<pid>-<uuid8>",
    "mutex_name": "Local\\FireLoopAccept-<pid>-<uuid8>",
    "events_pipe_name": "...-events", "events_mutex_name": "...-events",
    "m2_pipe_name": "...-m2", "m2_mutex_name": "...-m2",
    "fireloop_home": "<本次临时 HOME，跑完已删除>",
    "default_pipe": "\\\\.\\pipe\\fireloop-implant",
    "default_mutex": "Local\\FireLoopAgent",
    "real_agent_detected": false,
    "default_pipe_before": false, "default_pipe_after": false,
    "default_mutex_before": false, "default_mutex_after": false,
    "b1_test_registry_prefix": "fireloop-test-<uuid8>"
  },
  "options": {"skip_graceful_exit": false, "enable_desktop_events": false, "enable_result_window": false},
  "summary": {
    "total": 39, "passed": 36, "failed": 0, "skipped": 3,
    "by_suite": {"m1a": {...}, "b1": {...}, "b2": {...}, "m2": {...}}
  },
  "exit_code": 0,
  "results": [
    {"id": "B1-7", "suite": "b1", "name": "...", "status": "PASS", "detail": "...", "duration_s": 0.90}
  ]
}
```

- `summary` 就是计数，CI/脚本直接读它；
- `results[].detail` 与终端 `——` 后面的内容一致，失败时看这里定位；
- `isolation` 是隔离自检证据：`default_pipe_before/after` 与 `default_mutex_before/after`
  必须一致，说明这次验收没有碰生产管道/互斥体；`b1_test_registry_prefix` 是注册表测试用的唯一前缀；
- `real_agent_detected = true` 表示跑验收时机器上已有真实 agent 常驻（这是正常且安全的情况）。

默认结果文件写在 `%TEMP%\fireloop-acceptance\`，**不进仓库**；这是有意保留的输出，
不属于测试残留（每次运行的文件名不同）。若要清掉，直接删该目录即可。

## 4. 隔离原理（为什么和真实常驻 agent 零冲突）

每次运行生成一套独立环境：

| 项 | 生产值（绝不用于写入/启动） | 本次验收值 |
|---|---|---|
| 命名管道 | `\\.\pipe\fireloop-implant` | `\\.\pipe\fireloop-accept-<pid>-<uuid8>`（B2 事件阶段再加 `-events`） |
| 单实例互斥体 | `Local\FireLoopAgent` | `Local\FireLoopAccept-<pid>-<uuid8>`（事件阶段再加 `-events`） |
| 数据目录 | `%LOCALAPPDATA%\FireLoop\` | `%TEMP%\fireloop-accept-home-<pid>-<uuid8>-XXXX\`（`FIRELOOP_HOME` 覆盖） |
| B1 注册表前缀 | `fireloop` / 右键、自启名 `FireLoop` | `fireloop-test-<uuid8>` → 右键/自启名派生为 `FireLoop-test-<uuid8>` |
| B1 备份目录 | `%LOCALAPPDATA%\FireLoop\backup\` | `%TEMP%\...\localappdata\FireLoop\backup\`（只给安装脚本进程改 `LOCALAPPDATA`） |
| M2 模型配置/结果 | `%LOCALAPPDATA%\FireLoop\{config,secrets}.json`、`results\` | 全部在临时 `FIRELOOP_HOME` 下；`model.base_url` 指向本机 mock LLM |

具体做法：

1. 测试 agent 用 `python -m fireloop.agent --pipe-name <隔离管道> --mutex-name <隔离互斥体>` 启动。
   `--mutex-name` 是 T3a 加的入口参数，不传时行为与原来完全一致（默认生产互斥体）。
2. 每次 CLI 调用都显式带 `--pipe-name <隔离管道>`，token 从临时 `FIRELOOP_HOME` 读；
   不会连到生产管道，也不会读用户真实 token。
3. 第二实例测试用隔离互斥体名 + 另一个隔离管道名，验证的是单实例机制本身。
4. B2 事件阶段写临时 `config.json`、用第二套隔离管道/互斥体再起一个 agent；
   文件事件只在临时白名单目录里造数据；剪贴板/前台窗口真实操作只在
   `--enable-desktop-events` 显式打开时做。
5. B1 只调用 `install/install.ps1` / `install/uninstall.ps1`：
   - 生产前缀的 **dry-run** 只预览、不写；
   - 真写只用唯一测试前缀 `fireloop-test-<uuid8>` 和派生的 `FireLoop-test-<uuid8>`，
     验证完用 `uninstall.ps1 -Apply -KeyPrefix <同一个测试前缀>` 删干净；
   - **生产前缀的 `-Apply` 验收永远不跑**；验收进程只读探测生产键是否存在并前后比对；
   - 备份目录通过给子进程改 `LOCALAPPDATA` 隔离到临时目录，不污染真实备份；
   - 若 uninstall 异常，兜底清场只会删测试前缀命名的键/值（代码里有
     `prefix 必须以 fireloop-test- 开头` 的安全闸，绝不碰生产键）。
6. 跨用户 SID 验收用 `C:\Users\Public\FireLoopCrossUser-<pid>-<rand>\` 共享目录 + 一次性计划任务
   以 fl_test 身份跑 CLI；密码只从环境变量/getpass 读，不落盘，任务用完立刻删除。
7. 套件里所有子进程都登记在册，清场只 `terminate/kill` **自己拉起的 pid**；
   代码里没有任何按镜像名/进程名批量杀进程的逻辑，不会误杀真实 agent。
8. 唯一的“生产目标”操作是**只读探测**：列一下 `\\.\pipe` 目录、`OpenMutexW` 打开再
   `CloseHandle` 检查生产互斥体、用 winreg 只读查询生产键与 Run 值。
   这些都不会创建、占用、修改或关闭别人的东西。
9. M2 模型链路：验收进程自己在本机 `127.0.0.1` 起 mock LLM 服务，临时 HOME 里的
   `config.model.base_url` 指向它；假 key 只写临时 `secrets.json`。真实
   `%LOCALAPPDATA%\FireLoop\secrets.json` / `config.json` 只做 size+mtime 的**只读快照**
   前后比对（M2-8），不读内容、不修改。结果窗口在验收里由 `ui.show_result_window=false`
   关掉；`--enable-result-window` 的冒烟和 agent 可能拉起的结果窗口进程按临时 HOME
   路径精确清扫，避免弹窗和残留进程。

隔离自检（第 13 项）会在验收开始前后各做一次生产管道/互斥体只读探测，前后状态必须一致；
同时从日志里核对测试 agent 实际使用的管道名和互斥体名确实是本次隔离名。任何一项对不上都记 FAIL。
B1-9 / B1-6 会单独复核生产注册表键在全程没有被创建或修改。

**结论：真实 agent 常驻时，验收照样能跑；套件既连不到它，也不会杀它，更不会动生产注册表。**

## 5. 真实 agent 常驻场景怎么验（QA 自测方法）

当前机器上真实 agent 没在跑时，可以手工模拟这个场景（QA 交付前要做一次）。
开两个终端，**终端 A** 当前台常驻 agent，**终端 B** 跑验收：

```powershell
# 终端 A：用生产管道名 + 生产互斥体名起 agent（临时 FIRELOOP_HOME，不污染真实数据目录）
cd D:\ds植入式
$sim = New-Item -ItemType Directory -Path "$env:TEMP\fl-real-agent-sim" -Force
$env:FIRELOOP_HOME = $sim.FullName
$env:PYTHONPATH = "$PWD\src"
python -m fireloop.agent        # 保持前台运行，看到“已启动，管道 \\.\pipe\fireloop-implant”

# 终端 B：生产管道/互斥体此时都被占着，照常跑验收
cd D:\ds植入式
$env:PYTHONPATH = "$PWD\src"
python tests\acceptance\run_m1a_acceptance.py

# 回到终端 A：确认常驻 agent 还在、还能服务，然后 Ctrl+Break 正常停掉
python -m fireloop.cli ping     # 应打印 pong
```

期望结果：验收按当前配置给出预期的 PASS/SKIP 计数（全量默认是 44 PASS / 4 SKIP，
其中 SKIP 是桌面事件 2 项 + 跨用户 1 项 + 结果窗口 1 项，与真实 agent 无关）；
JSON 里 `real_agent_detected = true`、`default_pipe_before = default_pipe_after = true`，
且终端 A 的 `ping` 返回 `pong`（说明没被打扰）。
验证完在终端 A 按 Ctrl+Break 停掉 agent，删掉 `$env:TEMP\fl-real-agent-sim` 目录即可。

注意：给模拟 agent 用临时 `FIRELOOP_HOME` 只是为了避免往真实的
`%LOCALAPPDATA%\FireLoop\` 写日志/token；管道名和互斥体名是生产名，
冲突面与真实常驻 agent 完全一致。

## 6. Ctrl+Break 优雅退出项与 `--skip-graceful-exit`

两处会给测试进程投递 `CTRL_BREAK_EVENT`（等价用户按 Ctrl+Break），**默认必须真测**：

- M1a 的 8a 项：主测试 agent 退出码 0、打印“已退出”，9b 核对日志 `agent_stop`；
- B2 的 B2-9 项：事件阶段的第二个 agent 退出码 0，`watcher_stopped` / `events_stopped` 齐全，
  无 `stop_timeout`。

两种环境限制：

- 运行套件的地方**没有控制台**（例如某些计划任务/服务上下文）时，Windows 拒绝投递
  `CTRL_BREAK`（`GenerateConsoleCtrlEvent` 失败，错误 6）。套件会自动把对应项标成 SKIP，
  并用强制终止停掉测试进程，**不会**算成产品缺陷，其他项照常跑；
- 明确知道当前终端不支持时，也可以手工加 `--skip-graceful-exit`，效果同上。

只要环境有控制台（普通 PowerShell 终端、IDE 终端都算），就必须让它真跑；
如果相关项 FAIL，说明优雅退出回归了，按 FAIL 处理，不能用 SKIP 掩盖。

## 7. 桌面事件（剪贴板 / 前台窗口）开关

B2-7（剪贴板）和 B2-8（前台窗口）默认 **SKIP**——真实操作会干扰当前桌面/剪贴板，
**SKIP 不算通过**。

加 `--enable-desktop-events` 才会真测：

- **剪贴板**：先尽力保存当前文本剪贴板，写入一段唯一测试文本，等 `event_dispatch`；
  验证只记格式/长度/是否文本、没有正文；最后把原文本写回去。
  **如果原剪贴板不是文本（图片/文件等），会被测试文本覆盖、无法还原**——这是显式开关的已知代价，
  只在你确实能接受时打开。
- **前台窗口**：创建带唯一标题的测试窗口并切到前台，等 `foreground_changed` 事件；
  验证只有进程名/标题、没有窗口内容；随后销毁窗口并尽力把原前台窗口恢复。

两项都只在 `--enable-desktop-events` 下运行；不开就是 SKIP，交付报告里要写清楚。

## 8. 跨用户 SID 拒绝验收（B2-10 + 独立脚本）

背景：命名管道默认 DACL 通常只允许同一用户/SYSTEM/管理员连接，标准账户很可能在
`CreateFile` 阶段就被 Windows 拒绝（`ERROR_ACCESS_DENIED`），根本收不到协议层错误帧。

验收口径（Lead 2026-11-07 确认）：**"连不上/被拒" 即通过**，具体是哪一层要写明：

- Windows DACL 层拒绝（CLI 报连接失败/拒绝访问，agent 没收到请求）；
- 或协议层 SID 校验拒绝（agent 日志出现 `unauthorized`，CLI 退出码按协议映射）。

两种都不允许为了拿 `unauthorized` 帧去改管道 ACL。
同时必须满足：agent 不崩、当前用户后续 `ping` 正常。

账号由 Lead 的 task-9 创建（`fl_test` 标准账户，随机密码不写盘）。
主套件里没有账号或没有 `FL_TEST_PASSWORD` 时 B2-10 记 **SKIP**（明确不是 PASS）；
账号就绪后可以：

```powershell
# 交互输入密码（推荐，密码不落盘）
python tests\acceptance\run_cross_user_sid_check.py --user fl_test

# 或由 Lead 在会话里临时设环境变量后跑
$env:FL_TEST_PASSWORD = '<密码>'
python tests\acceptance\run_m1a_acceptance.py --suite b2   # B2-10 会真正执行
Remove-Item Env:\FL_TEST_PASSWORD
```

脚本会：建隔离 agent → 写共享目录和启动脚本 → 建一次性计划任务以 fl_test 跑 CLI →
收结果 → 删计划任务/共享目录/隔离 agent；失败路径也一样清场。

## 9. M2 模型链路验收（mock LLM）

M2 的模型链路验收**全程不联网、不碰真实 key、不调真实 DeepSeek API**：

- 验收进程自己用标准库 `http.server` 在 `127.0.0.1` 的临时端口起 mock LLM 服务
  （`POST /chat/completions`，OpenAI 兼容响应：固定 content + usage），并记录每个请求的
  path / headers / body 供断言；
- 临时 FIRELOOP_HOME 里写 `config.json`（`model.base_url` 指向 mock、
  `ui.show_result_window=false`）和 `secrets.json`（假 key `sk-test-<uuid>`）；
- 每个场景用完即停测试 agent；mock 服务在 M2 阶段结束时关闭；
- 真实 `%LOCALAPPDATA%\FireLoop\secrets.json` / `config.json` 只做**只读快照**
  （size + mtime，不读内容）前后比对，M2-8 会断言完全没被碰过；
- 无 key 场景会显式从子进程环境里移除 `DEEPSEEK_API_KEY`，防止机器上的真实环境变量混进来。

场景（`--suite m2` 或默认全跑时自动执行）：

1. **全链路**：`cli file` → agent 入队（`queued=True` 回显）→ 读文件 → mock 模型 →
   `<临时home>\results\result-*.md`（内容=mock 返回、usage 正确）→ 日志
   `task_enqueued` / `task_processed` / `model_request` / `model_response` 齐全；
   同时断言 mock 收到的请求体：`model`、`stream=false`、`max_tokens`、
   `thinking={"type":"disabled"}`（task-18 起）、Authorization 是本次假 key；
2. **普通 task** 仍回显 M1 的“收到任务”，且 mock 0 次调用；

## 13. 后续里程碑怎么扩

1. 新验收项写成一个返回详情字符串的函数，用 `check(ctx, "<id>", "<名称>", fn, suite="bX")` 注册；
   失败用 `require(条件, "现场说明")`，不适用用 `raise _Skip("原因")`，不要裸抛异常。
2. 套件按阶段组织：`checks_m1a.py` / `checks_b1.py` / `checks_b2.py` / `checks_m2.py`（内含 mock LLM 服务），
   入口 `run_m1a_acceptance.py` 按“同一个测试 agent 的生命周期”编排；
   新里程碑可以在 `harness.Context` 里加隔离字段，再新增 `checks_*.py`。
3. 必须继续用 `ctx.pipe_name` / `ctx.mutex_name` 起的隔离 agent 和 `ctx.run_cli(...)`；
   **禁止**在验收里出现生产管道名、生产互斥体名的启动/连接操作。
4. 涉及真实系统级改动（注册表、右键菜单、开机自启、桌面操作）时，一律：
   生产前缀 dry-run / 测试前缀真写 + 测完删除；真实桌面/剪贴板操作放显式开关且默认 SKIP；
   并在本文档补验收项和清理步骤。
5. 每个里程碑完成后，本文第 9 节验收项清单、第 13 节记录都要更新。
