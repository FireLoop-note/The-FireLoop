## 1. 前置条件

| 项 | 要求 |
|---|---|
| 系统 | Windows 11（本机） |
| 脚本宿主 | Windows PowerShell 5.1 **或** PowerShell 7（pwsh）。本机只装了 5.1，pwsh 7 兼容性未实机验证 |
| Python | `D:\Python\pythonw.exe`（3.15.1）。可用 `-PythonExe` 指定别的路径，但必须存在 |
| 项目路径 | `D:\ds植入式` |

**执行策略**：本机 PowerShell 执行策略是 `Restricted`，直接跑 `.ps1` 会被拦。命令里必须带 `-ExecutionPolicy Bypass`，例如：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\ds植入式\install\install.ps1
```

**不再需要 PYTHONPATH**。注册表命令统一走 `install/launch.py` 启动器，它自己把 `<项目根>\src` 插进 `sys.path`（见第 2 节）。安装脚本的 `[预检]` 会实际从 `C:\Windows` 跑一次启动器，预检不过会直接报错退出、不写注册表。

## 2. 启动器 install/launch.py

为什么有它：项目是 `src/` 布局，`pythonw -m fireloop.cli` 要求 `src` 在 `sys.path`（PYTHONPATH 或把包装进 site-packages）。原来注册的命令不带这个路径，从资源管理器/注册表拉起时会 `ModuleNotFoundError`，而 `pythonw` 没控制台、失败是静默的，表现就是"右键/链接没反应"。

启动器做的事：

1. 用 `__file__` 推算项目根：`PROJECT_ROOT = Path(__file__).resolve().parent.parent`（本文件在 `<项目根>\install\launch.py`）；
2. 把 `<项目根>\src` 插到 `sys.path` 最前面；
3. 按第一个参数转发：
   - `cli` → `fireloop.cli.main(剩余参数)`，退出码原样透传（0 成功 / 1 agent 没运行 / 2 超时 / 3 协议错误 / 4 内部错误）；
   - `agent` → `fireloop.agent.main(剩余参数)`，退出码透传（0 正常退出 / 1 已有实例）；
   - 启动器自身参数错误 → 退出码 2。

它**不改环境变量、不依赖工作目录**，注册表里只需要写一份稳定命令。

手动用法（一般用不到，排障用）：

```powershell
D:\Python\python.exe  D:\ds植入式\install\launch.py cli ping
D:\Python\python.exe  D:\ds植入式\install\launch.py cli file "D:\资料\示例.txt"
D:\Python\python.exe  D:\ds植入式\install\launch.py cli uri "fireloop://task?text=hello"
D:\Python\python.exe  D:\ds植入式\install\launch.py agent --pipe-name "\\.\pipe\fireloop-test" --mutex-name "Local\FireLoopTest"
D:\Python\python.exe  D:\ds植入式\install\launch.py show --help
```

### 2.1 结果展示器入口（install/show.py）

M2 起，agent 处理完一个任务（例如右键文件交给模型）后，会**以独立进程**弹一个结果窗口展示内容。拉起用的就是 `install/show.py`：

```powershell
# agent 任务处理器实际调用的形式（pythonw 无控制台，弹窗展示）
pythonw "<项目根>\install\show.py" --title <标题> --text-file <UTF-8 文件>
pythonw "<项目根>\install\show.py" --title <标题> --text <文本>

# 也可以走启动器转发
python "<项目根>\install\launch.py" show --title <标题> --text-file <文件>
```

- **谁调用**：`src/fireloop/task_processor.py`（M2-2）在模型返回后拉起；用户一般不需要手动跑。
- **不依赖 PYTHONPATH**：`show.py` 和 `launch.py` 一样，用 `__file__` 推算项目根后把 `<项目根>\src` 插进 `sys.path`；窗口实现本身在 `src/fireloop/result_window.py`（worker-cli 维护，参数细节 `--help` 可看）。
- **独立进程**：窗口不阻塞 agent；关掉窗口即退出，agent 继续常驻。
- **退出码**：

  | 码 | 含义 |
  |---|---|
  | 0 | 正常显示、用户关闭窗口 |
  | 2 | 参数错误（缺 `--title`、`--text`/`--text-file` 都不给等） |
  | 3 | 无 GUI 环境（TclError，转成可读错误） |
  | 4 | `show.py` 入口自己 import `fireloop.result_window` 失败（源码缺失/损坏；pythonw 无控制台，只能看退出码） |

- **注意**：不带 `--help` 直接跑会真的弹窗。验证/排障请用 `--help`；真实弹窗冒烟由 Lead 在联调时做。

## 3. install.ps1

### 3.1 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Apply` | 关（dry-run） | 不带只打印将创建/修改的键和值，**不写注册表、不建备份目录**；带了才真写 |
| `-KeyPrefix` | `fireloop` | 协议 handler 的注册表键名。测试必须用唯一前缀，如 `fireloop-test-<随机>` |
| `-PythonExe` | 自动探测 `D:\Python\pythonw.exe` | 路径不存在会明确报错、退出码 2 |

`KeyPrefix` 只允许字母开头，后面是字母、数字、`+`、`-`、`.`（URL scheme 命名规则）。

### 3.2 右键/自启名字从哪来（测试隔离关键）

| KeyPrefix | 右键菜单键名 / 自启值名（`HandlerName`） |
|---|---|
| `fireloop`（生产） | `FireLoop` |
| `fireloop-test-a1b2` | `FireLoop-test-a1b2` |
| `other` | `FireLoop-other` |

也就是说，用测试前缀真写时，**文件右键、文件夹右键、登录自启也全部用测试命名**，不会创建任何生产键（`fireloop`、`FireLoop` 右键、`Run\FireLoop`）。这是为了同时满足"测试必须用测试前缀"和"验收时生产键全程不存在"。

### 3.3 dry-run 输出怎么读

- `[预检]`：从 `C:\Windows` 实际跑一次启动器，不通过就退出码 2、不写注册表；
- `[1/4]`~`[4/4]`：4 类注册项；
- `[将创建键]` / `[将新增值]` / `[将更新值]` / `[无变化]`：相对现状的动作，`将更新值` 会打印当前旧值；
- `[现状]`：涉及键/值的快照，列出"原本不存在"的项；
- `[备份]`：dry-run 只打印**将来**的备份目录（`reg-<时间戳>`），不创建；
- 最后一行明确 `以上为 DRY-RUN，未写入任何注册表项`。

### 3.4 -Apply 做的事

1. 参数校验 + 启动器自检；
2. 生成计划；
3. **先备份**到 `%LOCALAPPDATA%\FireLoop\backup\reg-<yyyyMMdd-HHmmss>\`（无变化时不写注册表、也不建备份）；
4. 写注册表；
5. **逐项读回验证**，不一致退出码 1；
6. 在备份目录写 `install-result.json`（记录本次创建了哪些键、哪些父键要跟着清理）；
7. 打印完成信息 + 回退命令。

### 3.5 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（dry-run 或 -Apply 完成并验证通过；或已是最新状态） |
| 1 | 写入/验证失败 |
| 2 | 参数或环境错误（KeyPrefix 非法、Python 解释器不存在、启动器自检失败等） |

## 4. 注册内容（全部 HKCU）

命令统一走启动器。以生产前缀（`-KeyPrefix fireloop`，`<PythonExe>` = `D:\Python\pythonw.exe`，`<项目根>` = `D:\ds植入式`）为例：

| # | 键 / 值 | 内容 |
|---|---|---|
| 1 | `HKCU\Software\Classes\fireloop` | 默认值 = `""`；`URL Protocol` = `""` |
| 1 | `HKCU\Software\Classes\fireloop\shell\open\command` | 默认值 = `"<PythonExe>" "<项目根>\install\launch.py" cli uri "%1"` |
| 2 | `HKCU\Software\Classes\*\shell\FireLoop` | 默认值 = `交给火环` |
| 2 | `HKCU\Software\Classes\*\shell\FireLoop\command` | 默认值 = `"<PythonExe>" "<项目根>\install\launch.py" cli file "%1"` |
| 3 | `HKCU\Software\Classes\Directory\shell\FireLoop` | 默认值 = `交给火环` |
| 3 | `HKCU\Software\Classes\Directory\shell\FireLoop\command` | 默认值 = `"<PythonExe>" "<项目根>\install\launch.py" cli file "%1"` |
| 4 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `FireLoop` 值 | `"<PythonExe>" "<项目根>\install\launch.py" agent` |

值类型都是 `REG_SZ`。注意：注册的只是"系统身份"，CLI 的 `file` / `uri` 子命令由 task-6 实现，已就绪。

## 5. 备份

- 位置：`%LOCALAPPDATA%\FireLoop\backup\reg-<yyyyMMdd-HHmmss>\`
- `before.json`：安装前现状。每个键是否存在、每个值的名字/类型/旧数据；Run 值单独记录；"原本不存在"的项 `exists: false`，另外记录哪些父键原本不存在（卸载时据此清理空父键）。
- `*.reg`：对安装前**已存在**的 `scheme` / `file-verb` / `dir-verb` 键用 `reg export` 导出的完整子树（路径里带 `*` 也实测可导出）。
- `install-result.json`：安装完成后写，记录本次创建的键、需要清理的空父键、目标 Run 值。
- 备份目录只增不改、脚本不自动删。确认不需要后手动移入回收站即可。

手动恢复某个键：

```powershell
reg import "C:\Users\<你>\AppData\Local\FireLoop\backup\reg-20261107-171346\scheme.reg"
```

## 6. uninstall.ps1

### 6.1 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Apply` | 关（dry-run） | 不带只列出将删除的键和值；带了才真删 |
| `-KeyPrefix` | `fireloop` | 必须和安装时相同 |
| `-Force` | 关 | 即使内容看起来不是火环建的也强制删除（正常不需要） |

卸载不需要 `-PythonExe`：即使 Python 被删了也能卸干净。

### 6.2 行为

1. 默认 dry-run：按 4 类列出路径和当前值，标注 `[将删除]` / `[跳过] 不存在` / `[警告] 看起来不是火环创建的`；
2. `-Apply` 时只删**约定路径**：
   - 协议键（整棵子树）、两个右键 verb 键（整棵子树）、`Run\<HandlerName>` 这一个值；
   - 删前做内容归属检查：协议键要有 `URL Protocol`，或 command 含 `launch.py ... cli uri`（兼容旧格式 `fireloop.cli uri`）；右键键默认值要是 `交给火环`，或 command 含 `launch.py ... cli file`；Run 值要含 `launch.py ... agent`（兼容旧格式 `fireloop.agent`）；空键视为上一次安装中断残留，可删。**内容对不上就跳过并警告**，不误删别人的东西；`-Force` 才强制；
   - 根据最近一次安装的 `install-result.json`，把安装时创建、现在已经空掉的父键（本机实测是 `HKCU\Software\Classes\Directory\shell`）一起清掉；安装前就存在的父键（如 `HKCU\Software\Classes\*`、`*\shell`）只删自己的子键，不删它们；
   - 不删除备份目录。
3. 删完逐项验证不存在；再次运行是幂等的（全部 `[跳过] 不存在`，退出码 0）。
4. 不会恢复安装前的旧值（旧值在备份里，需要时手动 import）。

### 6.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（含本来就没有东西可删） |
| 1 | 删除后仍有残留（包括按保护规则跳过的非火环内容；要清加 `-Force`） |
| 2 | 参数错误 |

## 7. 回退方法

系统级改动，回退两步：

1. **正常回退**：`uninstall.ps1 -Apply`（同一 `-KeyPrefix`）；
2. **手动回退**：
   ```powershell
   # 删 4 类键/值（生产命名）
   reg delete "HKCU\Software\Classes\fireloop" /f
   reg delete "HKCU\Software\Classes\*\shell\FireLoop" /f
   reg delete "HKCU\Software\Classes\Directory\shell\FireLoop" /f
   reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v FireLoop /f
   # 需要恢复旧值时，从备份目录 import .reg（见第 5 节）
   ```
3. 不需要重启 explorer、不需要重启系统。资源管理器右键/协议关联若没立刻生效，注销重登一次即可（脚本不会替你重启 explorer）。

## 8. 安全边界（写死在脚本里）

- 注册表访问统一走一个入口，**只接受 `HKCU\...` 路径**，其他路径（含 HKLM）直接抛错；
- 不写系统服务、不碰 explorer、不碰其他用户注册表、不装任何软件、不联网；
- 不写系统级环境变量（PYTHONPATH 不需要了，启动器自带路径）；
- 不删除自己的备份；删文件（测试清场用）一律进回收站。
