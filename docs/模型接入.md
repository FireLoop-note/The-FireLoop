## 0. 一句话

标准库 `urllib` 直连 DeepSeek 的 OpenAI 兼容接口（`POST {base_url}/chat/completions`），零第三方依赖；
key 从环境变量或 `%LOCALAPPDATA%\FireLoop\secrets.json` 读取，**代码、日志、异常、测试、文档里都不出现真 key**。

## 1. 接口

### 1.1 `secrets.load_api_key() -> str | None`

读 DeepSeek API key。来源优先级（高 → 低）：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | 环境变量 `DEEPSEEK_API_KEY` | 空串/纯空白视为没设置，继续看文件 |
| 2 | `%LOCALAPPDATA%\FireLoop\secrets.json` 的 `deepseek_api_key` 字段 | 路径跟着 `paths.home()` 走，测试可用 `FIRELOOP_HOME` 覆盖 |

行为：

- 文件不存在、没有该字段、字段值为空串/非字符串 → 返回 `None`；
- 文件编码 UTF-8，**带不带 BOM 都能读**（Windows PowerShell 5.1 写出的文件默认带 BOM，本机真实文件就是这种）；
- 文件坏了（坏 JSON / 坏 UTF-8）、读取失败（权限等 IO 错误）→ **不抛异常**，返回 `None`，
  并在 `logs/agent-YYYYMMDD.jsonl` 记一条 `secrets_error` warning；
- warning 只记原因、路径、错误类型，**不记文件内容，不记 key 片段**；
- 返回的 key 已 `strip()`。调用方拿到后不要再写进任何日志或错误信息。

### 1.2 常量

```python
llm.DEFAULT_BASE_URL = "https://api.deepseek.com"
llm.DEFAULT_MODEL = "deepseek-flash"
llm.DEFAULT_TIMEOUT_S = 90.0
llm.DEFAULT_MAX_TOKENS = 800
llm.ERROR_CODES  # frozenset，见第 4 节
```

### 1.3 `llm.chat(...) -> dict`

```python
chat(
    messages: list[dict],
    *,
    model: str = DEFAULT_MODEL,
    base_url: str = DEFAULT_BASE_URL,
    api_key: str | None = None,
    timeout_s: float = 90.0,
    max_tokens: int = 800,
) -> dict
```

- 发请求：`POST {base_url}/chat/completions`，`base_url` 尾斜杠可有可无；
- 请求头：`Content-Type: application/json`、`Authorization: Bearer <key>`；
- 请求体（`messages` 原样透传，不改写、不裁剪）：

  ```json
  {
    "model": "deepseek-flash",
    "messages": [{"role": "user", "content": "..."}],
    "max_tokens": 800,
    "stream": false,
    "thinking": {"type": "disabled"}
  }
  ```

  **固定关掉深度思考**：请求体始终带 `"thinking": {"type": "disabled"}`（顶层不再传
  `reasoning_effort`）。原因（Lead 真实 API 实测）：DeepSeek 默认 thinking 开启，
  `max_tokens=16` 时 `completion_tokens` 全被 reasoning 吃掉、`content` 返回空串；
  加上 `thinking.disabled` 后同一个请求 `content="收到"`、0.75s、`completion_tokens=1`。
  文件摘要属于短任务，不需要深度思考，关掉更快、更省 output tokens，也避免"模型调了但正文是空的"。
  以后若真需要思考模式，只改 `llm.py` 里 `_THINKING_DISABLED` 一处即可（不推荐）。
- 返回：

  ```python
  {
      "content": "模型回复正文（允许空串）",
      "usage": {"prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0},
      "model": "接口返回的模型名（缺失时回退为请求的 model）",
  }
  ```

  `usage` 缺失字段、类型不对、负数一律按 0 处理。
- key 解析：`api_key` 参数非空就用它；否则调 `secrets.load_api_key()`；仍没有 → `LLMError("no_key")`，
  **不会发出请求**。
- 单次调用、**没有自动重试**：失败就抛错，由调用方决定是否重试（避免失败重试造成重复计费）。
- 每次调用都重新读 key（不做内存缓存），换 key 后下一次调用即生效。
- `llm.chat` 自身**不写日志**；要记日志的调用方只记 model / usage / 耗时 / 成功与否。

### 1.4 单测 mock 接缝

网络调用收在一个函数里，方便测试替换，签名不要随便改：

```python
_http_post(url, headers, body_bytes, timeout_s) -> (status, body_bytes)
```

`tests/test_llm.py` 就是 mock 它：测试默认把 `_http_post` 换成一调就 `AssertionError` 的替身，
任何漏 mock 的用例都会当场炸掉，**测试全程不联网**。

## 2. key 存放与隐私口径

### 2.1 放哪

| 项 | 值 |
|---|---|
| 首选 | 环境变量 `DEEPSEEK_API_KEY`（仅调试/临时测试用，不建议长期放这里） |
| 正式 | `%LOCALAPPDATA%\FireLoop\secrets.json`，字段名 `deepseek_api_key` |

`secrets.json` 内容格式（**下面是占位符，不是真 key**）：

```json
{"deepseek_api_key": "<你的 DeepSeek API key>"}
```

- 该文件在 `%LOCALAPPDATA%` 下，**不在仓库里**；仓库 `.gitignore` 也挡了 `secrets*.json`、`*.key`；
- 文件编码 UTF-8 即可，带 BOM 也能读（推荐用编辑器的"UTF-8 with BOM"或"UTF-8"都行）；
- 文件权限（ACL）已收紧为仅当前 Windows 用户可读，不需要每天处理；
- 不要把 key 贴进聊天、issue、文档、命令行历史；不要 `type secrets.json` 或 `Get-Content` 打印它。

### 2.2 隐私口径（写死的约定）

- key 只出现在一个地方：`Authorization` 请求头。不进 URL、不进请求体、不进返回值；
- 不进日志：`llm.chat` 不写日志；`secrets` 的 warning 只记路径/原因/错误类型；
- 不进异常：`LLMError.message` 从不含 key；万一 DeepSeek 错误响应把 key 回显回来，
  `llm` 在拼错误信息前会把 key 字面量替换成 `***`（单测有专门用例）；
- 不返回给上层展示：调用方打印/回传错误时只输出 `code` + `message`；
- 测试：全部用假 key（`sk-test-...`），**测试绝不联网、绝不读真实 key**，
  `FIRELOOP_HOME` 指向临时目录。

## 3. 成本控制

本模块只负责"发一次请求"，钱主要花在调用侧（`task_processor`），约定如下：

| 参数 | 默认/位置 | 说明 |
|---|---|---|
| `model.enabled` | `config.json` 的 `model.enabled`，默认 `false` | 模型接入总开关；关了不会联网、不会调模型 |
| `model.max_file_chars` | `config.json`，默认 20000 | 送进模型的文件正文截断上限，文档/代码类处理的核心省钱参数 |
| `model.max_output_tokens` | `config.json`，默认 800 | 单次回复上限；`task_processor` 会以 `max_tokens` 参数传给 `llm.chat` |
| `thinking` | 固定 `{"type": "disabled"}`（`llm.py` 写死） | 关掉深度思考：output tokens 只花在正文上，避免 reasoning 吃光预算导致 content 空串 |
| `model.max_calls_per_day` | `config.json`，默认 100 | 每日调用配额；超限直接拒绝并给用户明确提示 |
| `timeout_s` | `llm.chat` 参数（默认 90），`config.model.timeout_s` 可覆盖 | 防止挂死；超时抛 `timeout`，不自动重试 |
| 无自动重试 | `llm.chat` 内部 | 失败由调用方决定重试，避免重复计费 |
| 用量统计 | `chat()` 返回的 `usage` | 调用方累计 `prompt_tokens`/`completion_tokens` 即可算账 |

`config.json` 的 `model` 段由 `src/fireloop/config.py` 统一读取和规范化（非法值回默认），
`task_processor` 读取后显式传给 `llm.chat`；**`llm.py` 自己不读 `config.json`**。
默认 `model.enabled=false` 是安全默认（不联网），要真正处理右键文件才需要手动打开。

单价请以 DeepSeek 官网价格页为准，本文不写死价格（会变）。真实模型调用只在验收时做一次，
不做 "先调一下试试" 的反复试探。

## 4. 错误码

所有失败统一抛 `llm.LLMError`，带 `code`（机器可读）和 `message`（简体中文，给人看）：

| code | 含义 | 常见原因 | 建议动作 |
|---|---|---|---|
| `no_key` | 没有可用 key | 环境变量没设、`secrets.json` 不存在/字段名不对/空串 | 按第 2.1 节配置 key |
| `network` | 网络层失败 | 断网、DNS 失败、连接被重置、代理问题 | 检查网络/代理，稍后重试 |
| `timeout` | 请求超时 | 网络慢、接口卡住（默认 90s） | 稍后重试；持续出现再查网络 |
| `http_error` | HTTP 状态码非 200 | 401 key 错、402 余额不足、429 太频繁、5xx 服务端问题 | 看 `message` 里的状态码和接口返回内容 |
| `api_error` | 接口业务错误（预留） | 当前实现**不会抛出**，留给以后需要区分的业务级错误 | — |
| `bad_response` | 响应结构不对 | 不是合法 JSON/UTF-8、缺 `choices`、缺 `choices[0].message.content` | 先看日志确认接口是否异常，必要时反馈 |

`http_error` 的 `message` 形如：`请求失败：HTTP 401（API key 无效或已失效）；接口返回：...`，
状态码一定带，接口返回的可读 `error.message` 会截断并抹掉 key 后附上。

## 5. 换模型 / base_url

### 5.1 用户配置（推荐）

改 `%LOCALAPPDATA%\FireLoop\config.json` 顶层的 `model` 段（不存在就新建，按需只写要改的字段）：

```json
{
  "model": {
    "enabled": true,
    "model": "deepseek-flash",
    "base_url": "https://api.deepseek.com",
    "max_output_tokens": 800
  }
}
```

- `enabled`：模型接入总开关，默认 `false`；不打开就不会调模型；
- `model`：模型名。默认 `deepseek-flash` 是项目约定值，**未做过真实 API 验证**；
  真实调用若报"模型不存在"，改成 DeepSeek 官方当前可用的模型名即可；
- `base_url`：接口根地址，尾斜杠会被规范化掉；换代理/兼容网关时改这里；
- 其余字段（`timeout_s`、`max_file_chars`、`max_calls_per_day`、`provider`、`file_enabled`）
  见 `src/fireloop/config.py` 的 `DEFAULT_MODEL_CONFIG`，非法值一律回默认；
- 配置由 `task_processor` 读取后传给 `llm.chat`；`llm.py` 本身不读配置文件。

### 5.2 代码里直接调

`llm.chat(..., model="deepseek-chat")`、`llm.chat(..., base_url="https://.../v1")`，
参数优先于模块常量 `DEFAULT_MODEL` / `DEFAULT_BASE_URL`（常量只是兜底默认值）。

### 6.2 已由 mock 单测覆盖（真实输出见交付报告）

- 正常响应：content / usage / model 解析，空 content 允许，model 缺失回退；
- 请求：URL 拼接（含尾斜杠）、请求头、请求体字段、messages 原样透传、
  请求体固定带 `thinking.disabled`（换 model/max_tokens/base_url 也带）、顶层不传 `reasoning_effort`、
  key 不进请求体、timeout/max_tokens 透传；
- 错误映射：HTTP 401/429/500/502、超时（含被 `URLError` 包裹的）、网络错误、
  坏 JSON、非 UTF-8、响应非对象、缺 choices、缺 message/content；
- 安全：各类错误的 `message`/`repr` 不含假 key；错误响应体回显 key 会被替换成 `***`；
- key 解析：显式 key 不读 secrets、空串回退、无 key → `no_key` 且不发请求；
- `secrets`：环境变量优先、空环境变量回退、临时 `FIRELOOP_HOME` 下的 secrets.json、
  UTF-8 BOM 文件、缺文件/缺字段/空值/坏 JSON/坏 UTF-8/读失败、日志里不出现 key。
