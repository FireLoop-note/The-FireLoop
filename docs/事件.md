# 事件子系统（M1b / B2）

配套文档：`docs/fire-loop-方案.md`、`docs/协议-v1.md`。
代码：`src/fireloop/events.py`、`file_watcher.py`、`clipboard_watcher.py`、`foreground_watcher.py`，
集成点：`src/fireloop/agent.py`。

**默认全关。** 不改 `config.json` 的话，agent 启动时不会创建任何监听线程、不产生任何事件，
M1a 的管道 + CLI 行为完全不变。

---

## 1. 配置

位置：`%LOCALAPPDATA%\FireLoop\config.json`（测试可用环境变量 `FIRELOOP_HOME` 覆盖数据目录）。
文件不存在、JSON 损坏、字段类型不对时，一律安全回落到默认配置并记 `config_error` 日志
（`level=warning`），**绝不影响 agent 启动**。

默认配置（也是 `events.load_config()` 的返回值）：

```json
{
  "events": {
    "enabled": false,
    "file": {"enabled": true, "watch_dirs": []},
    "clipboard": {"enabled": false},
    "foreground": {"enabled": false},
    "quota_per_hour": 120,
    "debounce_ms": 1000,
    "dedupe_window_s": 60
  }
}
```

开关优先级：`events.enabled` 是总闸，为 `false` 时下面三项全不生效。
总闸打开后，`file` / `clipboard` / `foreground` 各自独立控制。

> 注意 `file.enabled` 默认是 `true`，但因为总闸默认关、`watch_dirs` 默认空，
> 实际什么都不会监听。要开文件事件，必须同时给 `watch_dirs` 填白名单目录。

### 打开全部事件（示例）

把下面内容写进 `%LOCALAPPDATA%\FireLoop\config.json`：

```json
{
  "events": {
    "enabled": true,
    "file": {
      "enabled": true,
      "watch_dirs": ["D:\\资料", "C:\\Users\\你的用户名\\Desktop"]
    },
    "clipboard": {"enabled": true},
    "foreground": {"enabled": true},
    "quota_per_hour": 120,
    "debounce_ms": 1000,
    "dedupe_window_s": 60
  }
}
```

改完重启 agent 生效（当前没有热加载）。只想开文件事件就把 `clipboard` / `foreground`
的 `enabled` 设 `false`。

### 参数说明

| 字段 | 默认 | 含义 |
|---|---|---|
| `events.enabled` | `false` | 事件子系统总闸 |
| `events.file.enabled` | `true` | 文件事件分项开关 |
| `events.file.watch_dirs` | `[]` | 白名单目录列表；**不递归子目录**；不存在的目录记 `watcher_error` 后跳过 |
| `events.clipboard.enabled` | `false` | 剪贴板事件分项开关 |
| `events.foreground.enabled` | `false` | 前台窗口事件分项开关 |
| `events.quota_per_hour` | `120` | 滚动 1 小时内最多 dispatch 的事件数，超出丢弃并记 `quota_drop` |
| `events.debounce_ms` | `1000` | 同 `(source, kind)` 合并窗口；窗口内只发第一条，被合并条数记到下次的 `merged_count` |
| `events.dedupe_window_s` | `60` | 同 `fingerprint` 丢弃窗口 |

## 2. 事件形状

所有事件都是一个普通 dict（可直接 JSON 序列化）：

```json
{"ts": "2026-11-07T17:06:23.910+08:00", "source": "file", "kind": "created", "path": "...", "fingerprint": "..."}
```

- `ts`：EventBus dispatch 时补的本地时间 ISO 字符串（毫秒精度、带时区）；
- `source`：`file` / `clipboard` / `foreground`；
- `kind` + 元数据：见下表；
- `fingerprint`：去重键，由各 watcher 生成；
- `merged_count`：仅当上一次同 `(source, kind)` 事件有被去抖合并时出现。

| source | kind | 元数据（全部不含正文） |
|---|---|---|
| `file` | `created` / `modified` / `deleted` | `path`（完整路径） |
| `file` | `renamed` | `path`（新路径）；能配上对时带 `old_path`（旧路径） |
| `clipboard` | `clipboard_update` | `format_type`（主格式名，如 `CF_UNICODETEXT` / `HTML Format`）、`formats`（格式号列表）、`is_text`（bool）、`length`（文本格式的 `GlobalSize` 字节数，非文本为 `null`） |
| `foreground` | `foreground_changed` | `process`（进程名 basename，如 `msedge.exe`）、`title`（窗口标题，截断到 512 字符） |

### 三道闸（顺序固定）

1. **去重**：同 `fingerprint` 在 `dedupe_window_s` 内只发一次；
2. **去抖**：同 `(source, kind)` 在 `debounce_ms` 内合并，只发第一条，
   被合并的条数写到下一次同键事件的 `merged_count`；
3. **配额**：滚动 1 小时最多 dispatch `quota_per_hour` 条，超出丢弃并写 `quota_drop` 日志。

当前 M1b 的 dispatch 动作 = 写 `event_dispatch` 日志（+ 调用订阅回调，供后续 M2 的事件队列用）。
**不写管道、不推给模型**；协议 v1 不包含事件帧，事件推送如果要做是 M2 的事（需要升协议版本）。

## 3. 隐私口径（硬约束）

- **文件**：只记路径 + 变化类型，不读文件内容、不读大小/哈希；
- **剪贴板**：只记格式类型 / 长度 / 是否文本。实现只 `OpenClipboard` 读格式表和 `GlobalSize`，
  **绝不调用读取内容的逻辑、绝不修改剪贴板**；
- **前台窗口**：只记进程名 + 窗口标题，不截图、不读窗口内容、不模拟键鼠；
- 所有事件统一落 `event_dispatch` 日志；`EventBus` 还有一份正文关键字黑名单
  （`text` / `content` / `data` / `html` / `rtf` / `preview` / `image`），
  手滑塞进来的正文字段也不会进日志；
- 日志位置：`%LOCALAPPDATA%\FireLoop\logs\agent-YYYYMMDD.jsonl`。

**风险提示**：前台窗口标题本身可能包含文件名、网页标题、聊天对象名等敏感信息。
这是验收时确认的口径（"只记进程名 + 窗口标题"），但如果你不想让这些标题进日志，
就把 `events.foreground.enabled` 保持 `false`。文件路径同理。

## 4. 日志事件一览

| event | 什么时候写 |
|---|---|
| `events_started` | agent 启动事件子系统成功，带 `watchers` / 配额 / 去抖 / 去重参数 |
| `events_stopped` | agent 退出时 watcher 全部停止 |
| `watcher_started` | 单个 watcher 启动成功（`watcher=file/clipboard/foreground`） |
| `watcher_stopped` | 单个 watcher 停止 |
| `watcher_idle` | watcher 配置为开但没有可用目标（如文件 watcher 没有有效目录） |
| `watcher_error` | 目录不存在 / OpenClipboard 失败 / WinEvent 回调异常 / stop 超时等，`level=warning` |
| `event_dispatch` | 每条通过三道闸的事件（只含元数据） |
| `quota_drop` | 超出每小时配额被丢弃 |
| `event_callback_error` | 订阅回调自己抛异常（不影响其它订阅者和 watcher） |
| `config_error` | config.json 读失败 / 坏 JSON / 不是对象 |

## 5. 实现要点（给维护者）

- **文件**：ctypes 直调 `ReadDirectoryChangesW`，每个白名单目录一个 daemon 线程；
  overlapped I/O + `WaitForMultipleObjects`（I/O 完成事件 + 停止事件），
  `stop()` 里 `SetEvent` + `CancelIoEx`，**不会挂死**。通知用
  `FILE_NOTIFY_INFORMATION` 手工解析（纯函数 `parse_notifications`，可单测）。
  缓冲区溢出（返回 0 字节）记 `watcher_error` 后继续。
- **剪贴板**：daemon 线程里 `RegisterClassW` + `CreateWindowExW(HWND_MESSAGE)` 建隐藏窗口，
  `AddClipboardFormatListener` 收 `WM_CLIPBOARDUPDATE(0x031D)`；
  `stop()` 用 `PostThreadMessageW(WM_QUIT)` 退出消息循环，再移除监听、销毁窗口、注销窗口类。
  剪贴板被别的程序占住时 `OpenClipboard` 重试 5 次（每次 10ms），失败记日志跳过。
- **前台窗口**：daemon 线程里 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, ...,
  WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS)` + `GetMessage` 循环；
  回调里 `GetWindowThreadProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` →
  `QueryFullProcessImageNameW` 取进程名，`GetWindowTextW` 取标题；
  `stop()` 同样 `PostThreadMessageW(WM_QUIT)` + `UnhookWinEvent`。
- 所有 watcher 的线程都是 daemon；agent 退出时在 `finally` 里统一 `stop()`。
- 单个 watcher 启动/停止失败只记 `watcher_error`，不影响 agent 主流程和管道服务。

## 6. 测试与验收

### 单测（已随代码提交）

```powershell
cd D:\ds植入式
$env:PYTHONPATH = "$PWD\src"
D:\Python\python.exe -m unittest discover -s tests -p "test_events.py" -v
```

覆盖：EventBus 去抖/去重/配额（假时钟）、配置加载与回退、文件通知解析、
**真实临时目录文件冒烟**（创建/修改/改名/删除，带超时）、剪贴板/前台纯逻辑与开关 gating。

刻意不覆盖（防止干扰用户桌面）：真实剪贴板复制、真实前台窗口切换。
这两项按下面的步骤做行为验收。

### 真实冒烟验收（QA/Lead 跑）

准备：`$home = 临时目录`，在 `$home\config.json` 打开需要的开关（示例见第 1 节），
启动 agent 时设 `$env:FIRELOOP_HOME = $home`，并用独立的 `--pipe-name` / `--mutex-name`
避免和真实常驻 agent 冲突。

1. **文件**：在 `watch_dirs` 里的目录创建/修改/改名/删除一个临时文件；
   查 `$home\logs\agent-*.jsonl`，应看到对应 `event_dispatch`，
   `source=file`、`kind=created/modified/renamed/deleted`、`path` 正确，**没有文件内容字段**。
2. **剪贴板**（会短暂占用剪贴板，先复制好你想保留的内容）：
   随便复制一段文本；日志应出现 `event_dispatch source=clipboard kind=clipboard_update`，
   带 `format_type` / `is_text=true` / `length`，**没有任何正文**。
   验收后请把用户原来的剪贴板内容放回去（Ctrl+V 之前手动恢复）。
3. **前台窗口**：切换几个窗口（记事本/浏览器/资源管理器）；日志应出现
   `event_dispatch source=foreground kind=foreground_changed`，
   带 `process` / `title`，无窗口内容。
4. **退出**：Ctrl+C（或 Ctrl+Break）停 agent，退出码应为 0；
   日志末尾应有 3 条 `watcher_stopped` + `events_stopped`，**不能有 `watcher_error`（stop_timeout）**，
   进程不能挂住。
5. **默认关**：不写 config.json 启动，日志里**不能**出现 `events_started` / `watcher_started`，
   `ping` / `task` 行为与 M1a 一致。

辅助文件事件冒烟脚本（PowerShell，配合上面环境）：

```powershell
$target = Join-Path $watchDir "fl-smoke.txt"
Set-Content -LiteralPath $target -Value "hello" -Encoding utf8
Add-Content -LiteralPath $target -Value "more" -Encoding utf8
Rename-Item -LiteralPath $target -NewName "fl-smoke-renamed.txt"
Remove-Item -LiteralPath (Join-Path $watchDir "fl-smoke-renamed.txt")
Start-Sleep -Seconds 2
Get-Content (Join-Path $home "logs\agent-*.jsonl") -Tail 20
```

### 开发期间真实跑过 / 没跑过的（2026-11-07，worker-events）

真跑过：

- 文件 watcher：真实临时目录创建/修改/改名/删除全部收到事件（单测冒烟）；
- agent 集成（默认全关）：真实 agent 进程 + CLI `ping`/`task` 成功、Ctrl+Break 退出码 0、
  日志无 `watcher_started`/`events_started`；
- agent 集成（全开）：真实 agent 进程启动 3 个 watcher，创建/修改文件收到 2 条
  `event_dispatch`，`ping` 仍正常，Ctrl+Break 退出码 0，3 个 watcher 全部 `watcher_stopped`，
  无 `watcher_error`；
- 剪贴板 watcher：起停不挂死；向隐藏窗口主动 `PostMessage(WM_CLIPBOARDUPDATE)` 后
  能成功枚举真实剪贴板格式（`HTML Format` + `CF_UNICODETEXT` 等），
  事件只有格式/长度/是否文本，无正文；**没有真实复制触发验证**（留给验收）；
- 前台 watcher：起停不挂死；用当前真实前台窗口句柄直接调回调，
  取到 `process=msedge.exe` + 真实窗口标题；**没有真实切换窗口触发验证**（留给验收）。

没跑过 / 已知限制：

- 真实用户复制内容、真实 Alt+Tab 切换窗口的端到端验收（按上面步骤做）；
- 文件 watcher 不递归子目录；监听的目录被删除/改名后，该目录线程退出且不会自动重挂；
- 剪贴板事件 fingerprint 用的是"格式签名 + 文本长度"：同格式同长度、60s 内连续复制
  会被当成重复丢弃（内容不同也不发）——这是"不读内容"下的折中；
- 前台事件 fingerprint 用"进程名 + 窗口标识 + 标题"：同一个窗口 + 同一标题 60s 内重复聚焦会被去重；
- 事件只落日志，不写管道、不给模型；M2 若要消费事件需要另做队列/协议升级；
- watcher 线程异常后不会自动重启（M1b 接受，长期稳定性留给服务化阶段评估）。

## 7. 回退方法

纯用户态、无注册表、无服务、无多进程：

- 把 `%LOCALAPPDATA%\FireLoop\config.json` 里 `events.enabled` 改成 `false`（或删掉 config.json），
  重启 agent 即回到"只跑管道 + CLI"的 M1a 状态；
- 代码回退：`git checkout` 事件相关文件（events.py / *_watcher.py / agent.py 的集成段）
  不影响 paths/log/protocol 和管道逻辑。
